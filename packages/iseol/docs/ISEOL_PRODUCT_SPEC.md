# NPC 최종 제품 명세

상태: 사용자 확정 요구사항. 기존 파일명과 역사적 ISEOL 명칭은 보존하지만, 현재 사용자-facing 제품명은 NPC다. 아래 신규 기능은 구현 완료 선언이 아니다. 구현 현황은 [인벤토리](ISEOL_FEATURE_INVENTORY.md)를 따른다.

## NPC 명칭과 이설

`NPC`는 개인 AI 하나의 이름이 아니라 개인 세계, AI, 학습, 프로젝트, 협업, 성장 기록, 포트폴리오와 외부 연동을 연결하는 플랫폼 이름이다. 현재 확장명은 **Nexus Personal Console**로 사용한다.

플랫폼 안에서 동작하는 개인 AI 봇을 통칭해 **이설**이라고 부른다. 이설은 사용자마다 별도 프로필을 가지며 이름, 프로필 이미지 URL, 성격, 말투, 역할을 사용자가 설정할 수 있다. 프로필과 이후 기억은 인증된 사용자 영역에 귀속되고, 프로필이 없는 기존 사용자는 기본 이름 `이설`을 사용한다.

## 변하지 않는 핵심

기존 자동 개발, Idea Lab, 장기 Project Workspace, 웹 AI, Desktop Agent, Runtime/Harness, Evaluation, Web, Discord, 캘린더, 코드리뷰, GitHub/CI/배포를 모두 유지한다. 기존 scrum, 음성 공부/잔디, 음악, 공모전/투표/알림, Notion/Figma 연동도 보존한다. 기존에 비활성화된 채용 feed는 비활성 상태를 보존하며 팀 모집과 혼동하지 않는다.

사용자 여정은 아이디어를 설명하고 여러 실제 결과물을 체험한 뒤 한 후보를 프로젝트로 확정하고, 코드·history·Run을 유지하면서 개발하는 것이다. 후보 제목을 복제하거나 static mock을 실제 앱 생성으로 표시하지 않는다. 생성/배포/체험 가능/선택/프로젝트 완료는 별도 상태다. 여러 프로젝트와 여러 캠페인을 소유할 수 있다.

## 개인 영역과 성장

각 사용자는 profile, character, personal world, personal AI, private memory, project/learning/study activity, growth ledger, portfolio를 가진다. 캐릭터는 기록을 시각화하며 현실의 역량을 자동 보증하지 않는다.

성장 근거는 학습 답변, 실습 artifact, 검증 테스트, 리뷰, 문제 해결 설명, 프로젝트 적용과 팀 기여다. 시간/커밋 수는 활동량 지표로만 분리한다. 기여 actor는 human/AI/system와 실제 작성자/검증자를 구별한다. AI 코드 전체를 사용자 역량으로 귀속하지 않는다. 평가 오류 정정은 원기록 삭제 대신 superseding/reversal 이벤트로 처리한다.

개인 AI는 목표, 설명 선호, 과거 질문, 어려운 개념, 설계 결정, 팀 역할, 남은 작업을 근거와 함께 참조한다. 추정 수준은 추정으로 기록한다. 사용자가 기억을 열람·정정·삭제하고 공유 범위를 선택할 수 있어야 한다. 제안 권한과 외부 실행 권한은 분리한다.

## 프로젝트와 협업

solo, AI team, human team, mixed team을 지원한다. 프로젝트/스터디 membership에는 human/AI 구분, role, capabilities, 승인 범위, 가입/탈퇴 시점이 있다. AI 팀원의 권한은 소유자보다 클 수 없고 사람의 동의나 리뷰를 대신하지 않는다.

친구 관계는 상호 수락, 차단/신고를 포함한다. 개인 메시지와 커뮤니티는 별도 공개 범위다. 공동 프로젝트/스터디에는 모집 공고 → 지원 → 모집자 승인 → membership 생성 흐름이 있다. 지원은 가입이 아니며 private AI memory를 열람할 권한도 아니다. 공개 자료에 개인 학습 답변·실패 기록을 자동 첨부하지 않는다.

## 학습

필수 시작 입력은 **학습 분야 자유 입력 → 기간 버튼 → 하루 시간 버튼 → 학습 계획 만들기**뿐이다. 7/14/30/60/90일 및 직접 일수/목표일, 15/30/60/120분 및 직접 시간을 제공한다. 수준·목표 세부·선호는 선택 설정이다.

ISEOL이 현실적인 범위, 선수 개념, 주제 순서, 일별 분량, 복습, 중간/최종 점검을 생성한다. 계획 미리보기에서 목표·구간·오늘 할 일·예상 결과를 보고 시작/조건 수정/재생성을 선택한다. 일일 학습은 복습→설명→예시→질문→문제/실습→답변→피드백→재설명→기록→다음 안내다. 분야별 평가 방식은 달라도 공통 운영 템플릿을 사용한다.

결석/미완료/빠른 진도/막힘/시간·기간·목표 변경 시 완료 기록을 보존하며 새 계획 버전을 제안한다. 이해 버튼은 self-report이며 mastery 증거가 아니다. [학습 상세 명세](ISEOL_LEARNING_SPEC.md)가 구현 계약이다.

## 기존 기능과 연결

| 출발 | 연결 | 동의/근거 |
|---|---|---|
| 개발 중 지식 부족 | 학습 목표 초안 | 시작은 사용자 선택, 자동 외부 요청 없음 |
| 학습 실습 | Project work request 초안 | 실행은 프로젝트 권한/승인 별도 |
| 학습 일정 | 기존 Calendar | opt-in, 외부 일정 생성 idempotency |
| 학습/프로젝트 진행 | Discord | 사용자/팀 binding과 알림 설정, unknown 전송 자동 재시도 금지 |
| 활동 evidence | 성장 | event identity와 평가 version, 중복 가산 방지 |
| 사용자 검증 기여 | 포트폴리오 | claim별 evidence/actor, 사용자 편집 및 공개 승인 |
| 스터디 | 공유 수업/팀 과제 | 개인 답변·오개념은 private 기본값 |

포트폴리오는 문제/역할/구현/기술 이유/해결 과정/테스트·Git·배포·학습 적용을 source reference와 연결한다. AI가 쓴 문장도 draft로 표시하며 없는 PR/URL/기여를 생성하지 않는다.

## 완료 기준

제품 코드, 격리 테스트, 브라우저 사용자 동작, 운영 반영, 외부 계정 통합, 실제 ChatGPT Web 앱 생성은 각각 증거를 남긴다. 기존 기능의 외부 검증을 신규 성장 기능의 뒤로 무기한 밀지 않는다. 공개 다중 사용자 전환은 서버 인가, 개인/팀 데이터 격리, 삭제/보존 정책 및 사용자 단위 자원 제한을 통과한 후 진행한다.
