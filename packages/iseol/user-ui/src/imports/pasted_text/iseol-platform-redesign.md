# ISEOL — 전체 플랫폼 완성도 개선 및 모든 문제점 일괄 수정

당신은 시니어 프로덕트 디자이너, 프론트엔드 개발자,
게임 UI 디자이너, QA 엔지니어의 역할을 함께 수행합니다.

현재 제작된 ISEOL Platform UI/UX Redesign 프로젝트를
전수 조사하고, 발견된 모든 문제를 수정해주세요.

이번 작업은 일부 페이지를 개선하거나
추가 수정 방향만 제안하는 작업이 아닙니다.

기존 프로젝트 전체를 대상으로
문제 발견 → 원인 분석 → 실제 수정 → 전체 검증
과정을 하나의 작업으로 완료하는 것이 목표입니다.

작업 도중 홈 페이지만 개선하고 종료하거나,
이미지 교체만 진행한 뒤 나머지를 후속 작업으로
넘기지 마세요.

시간이나 실행 환경의 한계로 완료할 수 없는 항목은
완료했다고 주장하지 말고 정확히 보고해주세요.

src/App.tsx
src/app/routes.ts
src/index.css
src/components/*
src/pages/*
package.json
기존 이미지 및 기타 에셋

기존 페이지, 컴포넌트, 라우팅,
디자인 시스템 및 사용자 흐름을 전부 파악하세요.

각 페이지에서 다음 문제를 찾아주세요.

- 디자인 완성도가 부족한 부분
- 임시 이미지와 이모지
- 페이지 간 디자인 불일치
- 잘못된 레이아웃
- 작은 글자와 낮은 가독성
- 화면 밖으로 잘리는 요소
- 모바일에서 사용할 수 없는 기능
- 작동하지 않는 버튼
- 잘못된 페이지 이동
- 실제 기능이 없는 입력창과 검색창
- 가짜 진행률 및 성공 결과
- 실제로 없는 데이터가 표시되는 문제
- 사용자 입력이 유지되지 않는 문제
- 누락된 상태 화면
- 접근성 문제
- 렌더링 및 빌드 오류
- 이미지 누락과 잘못된 파일 경로
- 보안 또는 권한이 있는 것처럼 잘못 표현하는 UI

기존에 알려진 문제만 수정하지 마세요.

실제 프로젝트 전체를 다시 조사하고,
새로 발견한 문제도 모두 수정 대상에 포함해주세요.

코드에 존재하지 않는 기능을
이미 구현된 것으로 가정하지 마세요.

2. 이설의 디자인 방향
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ISEOL은 사용자가 디지털 캐릭터와 개인 AI를 가지고
프로젝트 개발, 학습, 협업 및 커뮤니티 활동을 진행하는
AI 기반 디지털 세계 플랫폼입니다.

ISEOL은 다음 세 가지 요소가 결합된 서비스입니다.

- 나만의 캐릭터와 세계가 존재하는 게임형 플랫폼
- 실제 개발 및 학습을 수행하는 생산성 도구
- 다른 사용자들과 소통하고 협업하는 소셜 플랫폼

현재의 일반적인 SaaS 대시보드 느낌을 개선하세요.

홈과 캐릭터 화면에서는 실제 게임 속 개인 공간처럼
캐릭터, 배경, 공간감과 세계관이 중심이 되어야 합니다.

그러나 코드 편집, 학습, 메시지 작성 등
실제 정보를 읽고 작업하는 화면은
가독성과 사용성을 우선해야 합니다.

모든 페이지를 같은 카드 레이아웃으로 만들지 마세요.

각 페이지의 목적에 적합한 레이아웃을 설계하면서도
모든 화면이 ISEOL이라는 동일한 세계에
속한다는 느낌을 유지하세요.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 임시 이미지와 에셋 전면 교체
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 가장 중요한 문제 중 하나입니다.

프로젝트에서 사용 중인 모든 캐릭터,
배경, 프로젝트 썸네일, 프로필 이미지,
업적 배지, 장식 이미지와 임시 아이콘을 확인하세요.

단순한 SVG 도형 조합이나 이모지를
정식 캐릭터·배경 이미지로 간주하지 마세요.

실제 서비스에 사용할 수준의 에셋으로 교체해주세요.

[사용자 캐릭터]

독창적인 ISEOL 사용자 캐릭터를 제작하세요.

필요한 표현:
- 기본 전신
- 프로필
- 작업 중
- 학습 중
- 대화 중
- 기쁨
- 생각
- 기본 대기 상태

같은 캐릭터의 얼굴, 의상, 비율과
색상이 모든 화면에서 일치해야 합니다.

[개인 AI 이설]

사용자 캐릭터와 명확히 구별되는
개인 AI 동반자 캐릭터를 제작하세요.

필요한 표현:
- 기본 전신
- 프로필
- 대화
- 아이디어 제안
- 작업 분석
- 사용자 확인 대기
- 결과 안내

이설은 단순한 별 이모지나
보라색 원으로 표현하지 마세요.

[환경 일러스트]

다음 공간을 같은 세계관과 아트 스타일로 제작하세요.

- 개인 세계 및 작업실
- Idea Lab 연구실
- 프로젝트 개발 작업실
- 학습 공간 및 도서관
- 팀 공동 작업실
- 커뮤니티 광장
- 캐릭터 꾸미기 공간
- 포트폴리오 전시 공간

모든 배경을 단순한 그라데이션이나
도형 조합으로 대체하지 마세요.

빛, 그림자, 원근감, 오브젝트,
인물과 배경 사이의 공간 관계를 고려하세요.

[프로젝트 및 사용자 이미지]

프로젝트 카드는 실제 프로젝트 스크린샷을
우선적으로 사용할 수 있는 구조로 변경하세요.

아직 실제 결과물이 없는 경우에는
콘셉트 이미지와 실제 스크린샷을 구분하세요.

사용자 프로필에는 실제 프로필 이미지나
개인 캐릭터를 사용할 수 있도록 구성하세요.

현재 존재하는 단순한 색상 원을
완성된 사용자 프로필 이미지로 사용하지 마세요.

[아이콘과 배지]

메뉴, 버튼, 상태 표시의 이모지를
일관된 아이콘 세트로 교체하세요.

업적 배지는 일반 메뉴 아이콘과 구분되는
독립적인 게임형 에셋으로 제작하세요.

획득하지 않은 업적을
획득한 것으로 표시하지 마세요.

[이미지 적용 기준]

- 실제 이미지 파일을 프로젝트에 포함
- 일관된 아트 스타일 유지
- 이미지의 출처와 사용 권한 확인
- 가능한 경우 투명 배경 캐릭터 사용
- WebP 등 적절한 이미지 형식 활용
- 원본 비율을 유지하고 이미지 찌그러짐 방지
- 필요에 따른 반응형 이미지 제공
- 로딩 실패 시 대체 이미지 또는 상태 제공
- 장식 이미지와 정보 전달 이미지 구분
- 필요한 이미지에 적절한 대체 텍스트 제공

다른 게임의 고유 캐릭터나 배경을
무단으로 복제하지 마세요.

이미지 생성 기능이 없다면
인터넷의 임의 URL이나 CSS 도형으로
작업을 완료했다고 위장하지 마세요.

실제 생성된 이미지와
생성되지 못한 이미지를 구분하여 보고하세요.

4. 디자인 시스템 전체 재정비
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재의 색상과 컴포넌트를 조사하고,
ISEOL 전용 디자인 시스템으로 통합하세요.

색상:

기본 세계관:
스카이블루, 블루, 라벤더.

AI 및 아이디어:
보라색 계열.

학습과 성장:
민트 및 초록 계열.

경험치와 업적:
노랑 및 오렌지 계열.

친구와 커뮤니티:
코랄 및 핑크 계열.

전문적인 작업 화면:
네이비와 가독성 높은 중립색.

색상을 단순히 무작위로 섞지 말고,
각 색상의 의미와 용도를 일관되게 관리하세요.

반드시 통일할 요소:

- 타이포그래피
- 색상 토큰
- 간격
- 그림자
- 모서리 크기
- 버튼 크기
- 입력창 디자인
- 카드 디자인
- 내비게이션
- 아이콘
- 상태 배지
- 로딩 UI
- 오류 UI
- 모달
- 드롭다운
- 캐릭터 표현
- 이미지 비율

작은 안내 문구를 제외한 주요 콘텐츠는
모바일에서도 충분히 읽을 수 있어야 합니다.

일반 본문은 14~16px 이상을 기본으로 검토하고,
중요한 모바일 메뉴를 9px처럼 작게 표시하지 마세요.

디자인 토큰과 재사용 가능한 컴포넌트를 정의하여
페이지별 임의의 색상·크기 하드코딩을 줄이세요.

기존의 Stayfolio 기반 디자인 문서는
ISEOL이 사용자 요청으로 생성하는
웹사이트의 기본 디자인 참고 자료입니다.

ISEOL 플랫폼 자체의 게임형 디자인과 혼동하지 마세요.

또한 생성된 웹사이트의 미리보기 안에는
ISEOL 플랫폼의 색상과 컴포넌트를 적용하지 마세요.

5. 홈 화면 전면 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 홈의 작은 캐릭터 영역과
반복되는 통계 카드 구조를 개선하세요.

홈의 가장 큰 시각적 요소는
사용자의 디지털 캐릭터가 존재하는 개인 세계입니다.

중앙에는 충분한 크기의 작업실 일러스트와
사용자 캐릭터, 개인 AI 이설을 배치하세요.

사용자가 실제로 활동하는 공간처럼 보여야 합니다.

프로젝트 작업실, 학습 공간, 커뮤니티 광장 등은
단순한 텍스트 카드가 아니라
세계 안의 서로 다른 장소처럼 표현하세요.

다음 정보는 화면에서 쉽게 찾을 수 있어야 합니다.

- 현재 진행 중인 프로젝트
- 오늘의 학습
- 사용자 확인이 필요한 AI 작업
- 캐릭터 성장 정보
- 오늘의 실제 미션
- 최근 활동
- 주요 기능으로 이동하는 버튼

캐릭터와 배경 때문에
중요한 작업 버튼이 가려지지 않도록 하세요.

현재 프로젝트와 학습 기록이 없는
신규 사용자 홈 화면도 제작하세요.

실제 사용자 데이터가 없다면
미리 정해진 레벨, 경험치, 프로젝트와
업적을 개인의 실제 기록처럼 표시하지 마세요.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
6. Idea Lab의 잘못된 상태 표현 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 Idea Lab의 생성 진행률과
후보작 표시 코드를 집중적으로 확인하세요.

실제 AI 실행 이벤트와 무관하게
setInterval로 진행률을 증가시키고
완료된 후보작을 표시하는 구조를
실제 서비스 동작으로 사용하지 마세요.

필요한 UI 상태:

- 입력 대기
- 요구사항 작성
- 실행 전 확인
- 요청 접수
- 실행 준비
- 실제 작업 진행
- 사용자 확인 대기
- 파일 생성 및 변경
- 테스트 및 빌드
- 미리보기 준비
- 생성 완료
- 실패
- 연결 끊김
- 결과 확인 불가

실제 데이터가 연결되지 않은 경우에는
'데모 화면' 또는 '연결 전' 상태로 명확히 표시하세요.

AI 실행 성공이나 빌드 성공을
임의로 만들어 표시하지 마세요.

실제 미리보기가 없는 후보작의
미리보기 버튼은 정상 작동하는 것처럼 표현하지 마세요.

프로젝트 승격 버튼도
실제 승격 가능 조건을 충족한 경우에만
활성화할 수 있는 구조로 설계하세요.

'아이디어 구체화하기'와
'프로토타입 만들기'는 서로 다른 기능입니다.

두 버튼이 같은 동작을 실행하는 문제를 수정하세요.

아직 실제 백엔드에 연결되지 않았다면
각각의 목적에 맞는 시연 상태 또는 안내를 제공하세요.

필수 영역:

- 프로젝트 정보
- 프로젝트 파일
- 현재 작업 요청
- 실행 계획

- 실제 작업 상태
- 변경 파일
- 테스트 결과
- 빌드 결과
- 실제 앱 미리보기
- 실행 로그
- 사용자 후속 요청

'AI가 완료했다고 응답한 상태'와
'실제 파일 변경 및 검증이 완료된 상태'를

코드 보기, 미리보기 등의 버튼을 모두 확인하세요.

사용자가 이해할 수 있는 비활성 또는 안내 상태로 처리하세요.

코드와 로그 영역은 캐릭터 일러스트보다
가독성과 작업 효율을 우선하세요.

15. 모든 버튼·입력·라우트 전수 검사
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전체 프로젝트에서 다음 코드를 찾아 확인하세요.

- button
- onClick
- input
- textarea
- select
- Link
- navigate
- href
- cursor-pointer
- disabled

각 요소가 실제로 어떤 행동을 수행하는지
확인하고 문제를 수정하세요.

대표적인 문제:

- 버튼이 클릭되지만 아무 일도 발생하지 않음
- 서로 다른 버튼이 같은 동작을 수행함
- 잘못된 페이지로 이동함
- 존재하지 않는 경로로 이동함
- 필터 버튼을 눌러도 목록이 바뀌지 않음
- 검색어를 입력해도 검색되지 않음
- 폼 검증 없이 완료 화면으로 이동함
- 선택 상태가 실제 데이터에 반영되지 않음
- 저장 버튼이 변경사항을 저장하지 않음
- 미리보기 버튼이 실제 미리보기를 열지 않음
- 사용자 확인이 필요한 작업이 자동 완료됨

모든 주요 버튼에는 명확한 동작을 연결하세요.

현재 UI 프로젝트에 실제 백엔드가 없어
구현할 수 없는 기능은
비활성 상태 또는 명확한 데모 화면으로 처리하세요.

작동하지 않는 버튼을
작동하는 것처럼 그대로 남겨두지 마세요.

또한 현재 존재하는 모든 라우트를 방문하여
화면이 정상적으로 렌더링되는지 확인하세요.

잘못된 경로의 404 화면도 제공하세요.

16. 누락된 페이지와 사용자 흐름
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

현재 존재하는 모든 페이지와
ISEOL 전체 서비스에 필요한 페이지를 비교하세요.

기존 화면에 탭이나 모달로 포함된 기능은
반드시 불필요하게 별도 페이지로 중복 생성할 필요는 없습니다.

하지만 다음 흐름을 사용자가 완주할 수 있는지 확인하세요.

1. 방문 → 회원가입 → 온보딩 → 내 세계
2. 내 세계 → Idea Lab → 후보작 → 미리보기 → 프로젝트
3. 프로젝트 → 개발 요청 → 승인 → 결과 확인
4. 학습 시작 → 계획 → 실제 학습 → 복습
5. 팀 모집 → 지원 → 팀 합류 → 공동 작업
6. 커뮤니티 → 프로필 → 친구 → 메시지
7. 활동 기록 → 포트폴리오 작성 → 미리보기
8. 설정 → 연동 상태 및 권한 확인

현재 프로젝트에 없는 화면이
이 흐름을 완성하는 데 필요하다면 추가하세요.

기존 기능과 겹치는 페이지를
불필요하게 중복해서 생성하지 마세요.

각 페이지와 주요 모달에서
사용자가 다음에 무엇을 해야 하는지
명확하게 알 수 있어야 합니다.

17. 모바일 및 반응형 전면 수정
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

다음 화면 폭에서 전체 페이지를 검증하세요.

- 390px 모바일
- 768px 태블릿
- 1024px 작은 데스크톱
- 1440px 데스크톱

특히 다음 문제를 확인하세요.

- 모바일에서 페이지가 가로로 넘침
- 텍스트가 잘림
- 캐릭터가 화면을 과도하게 차지함
- 버튼이 겹침
- 입력창이 화면 밖으로 나감
- 모달이 화면보다 커짐
- 하단 내비게이션이 콘텐츠를 가림
- 채팅 입력창이 화면 밖으로 밀림
- 프로젝트의 파일·코드·로그 영역을 사용할 수 없음
- 일부 메뉴에 접근할 수 없음

현재 '더 보기' 메뉴가 설정 페이지로만
이동하는 구조를 수정하세요.

모바일에서 전체 메뉴를 열면
ISEOL의 모든 주요 기능으로 이동할 수 있어야 합니다.

프로젝트 작업실은 모바일에서
파일, 작업, AI 대화, 실행 결과를
각각의 탭으로 사용할 수 있도록 구성하세요.

모든 주요 버튼은 모바일에서도
충분한 터치 영역을 확보해야 합니다.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
18. 접근성 및 실제 사용성
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전체 화면에서 다음 항목을 검증하세요.

- 텍스트와 배경의 충분한 대비
- 키보드만으로 메뉴 사용 가능
- 눈에 띄는 focus 상태
- 입력창과 label 연결
- 버튼의 접근 가능한 이름
- 아이콘 버튼의 설명
- 올바른 탭 이동 순서
- 모달의 키보드 접근성
- 상태 변경에 대한 안내
- 이미지 대체 텍스트
- 색상 외의 상태 구분 수단
- 과도한 애니메이션 방지
- reduced-motion 환경 지원

클릭 가능한 div를
접근 가능한 버튼으로 교체할 수 있는지 확인하세요.

상태 변화가 단순히 색상 변화에만 의존하지 않도록 하세요.

이미지가 로드되지 않아도
주요 기능을 사용할 수 있어야 합니다.

19. 코드 품질 및 상태 관리
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

전체 프로젝트를 점검하고 다음 문제를 수정하세요.

- 사용하지 않는 import 및 변수
- 중복 컴포넌트
- 잘못된 React key
- 잘못된 상태 초기화
- 불필요한 setInterval 및 타이머
- 정리되지 않는 타이머 및 이벤트
- 렌더링 중 불필요한 난수 생성
- 잘못된 타입 단언
- 반복되는 하드코딩
- 입력값 검증 누락
- 이미지 로드 실패
- 잘못된 라우팅
- 불필요한 전체 페이지 새로고침
- 오류 발생 시 빈 화면
- React 렌더링 경고
- 타입 오류
- 빌드 오류

공통 UI는 가능한 경우
재사용 가능한 컴포넌트로 통합하세요.

다만 리팩터링 과정에서 기존 페이지를
삭제하거나 정상 동작하던 기능을 손상시키지 마세요.

20. 실제 브라우저 검증
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

코드 수정만으로 작업을 완료하지 마세요.

실제 미리보기 브라우저에서

- 이미지 정상 표시
- 콘솔 오류 없음

- 로딩 및 오류 상태
- 빈 상태
- 모바일 레이아웃
- 텍스트 및 이미지 겹침
- 스크롤 동작

특히 다음 시나리오는 직접 확인하세요.

A. 회원가입 및 온보딩 화면 탐색
B. 홈에서 모든 주요 공간으로 이동
C. Idea Lab 입력과 상태 전환
D. 후보작 선택 및 미리보기 상태
E. 프로젝트 파일·작업·AI 패널 탐색
F. 학습 계획 및 문제 풀이
G. 캐릭터 꾸미기
H. 팀 모집 및 지원
I. 커뮤니티 게시글 탐색
J. 친구 및 메시지 화면
K. 포트폴리오 편집과 미리보기
L. 설정 변경 및 전체 메뉴 접근

실제 백엔드에 연결되지 않은 기능은
브라우저 UI 검증 완료와
실제 서비스 기능 검증 완료를 구분하세요.

데모 UI가 잘 동작한다고 해서
실제 AI 개발 및 사용자 간 통신이
검증됐다고 주장하지 마세요.

- 프런트엔드 빌드

이번 요청을 단순한 디자인 제안서 작성이나
문제 목록 제출로 끝내지 마세요.

검사한 페이지와 컴포넌트 수,

홈, Idea Lab, 프로젝트,

기존에 작동하지 않던 버튼,
입력창, 검색, 필터, 라우팅,
상태 관리 문제의 수정 결과.

기존 사용자 흐름에서 누락되어
새로 추가한 페이지 또는 모달.

타입 검사, 빌드, 페이지별 렌더링,
반응형 검증, 브라우저 기능 검증 결과.

통과했다고 표시하지 마세요.

[7] 남은 문제

완료하지 못한 항목이 있다면
파일 경로, 문제 원인,
현재 상태와 해결에 필요한 조건을 명시하세요.

[8] 최종 완료 판정

모든 필수 조건을 충족했다면
완료했다고 보고하세요.

아직 미완료 항목이 존재한다면
전체 작업을 완료했다고 보고하지 마세요.

한 줄로 끝내지 말고,
